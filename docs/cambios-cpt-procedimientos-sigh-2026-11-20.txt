1. DESCRIPCIÓN DEL CAMBIO:
--------------------------------------------------------------------------------
Se reemplazaron las consultas directas en texto plano (SELECT) a las tablas
FactCatalogoServicios y FactCatalogoServiciosHosp para alinearse con los
procedimientos almacenados nativos que utiliza el sistema hospitalario SIGH / GalenHos.

2. PROCEDIMIENTOS ALMACENADOS UTILIZADOS:
--------------------------------------------------------------------------------
A) dbo.FactCatalogoServiciosHospFiltraPorPuntoCargaTipoFinanciamiento
   - Propósito: Buscar servicios/procedimientos CPT habilitados para un
     Punto de Carga específico (área/servicio) y Tipo de Financiamiento (SIS = 2).
   - Parámetros:
       @idPuntoCarga          (INT, ej. 716)
       @idTipoFinanciamiento  (INT, ej. 2)
       @idFiltroTipo          (INT, 1=Código, 2=Nombre)
       @Filtro                (VARCHAR, texto ingresado)
       @TipoServicioOfrecido  (INT, 1=Solo CPT)

B) dbo.FactCatalogoServiciosXidTipoFinanciamiento
   - Propósito: Obtener el registro hospitalario puntual (precios, condición, activo)
     de un producto según el financiamiento del paciente.
   - Parámetros:
       @idProducto            (INT)
       @IdTipoFinanciamiento  (INT)

3. ARCHIVOS MODIFICADOS:
--------------------------------------------------------------------------------
- backend/src/modules/catalogos/repositories/factCatalogoServiciosRepository.js:
    * Se implementó `buscarServicios(buscar, idPuntoCarga, idTipoFinanciamiento)`
      invocando executeProcedure('dbo.FactCatalogoServiciosHospFiltraPorPuntoCargaTipoFinanciamiento').
    * Se implementó `obtenerServicioPorFinanciamiento(idProducto, idTipoFinanciamiento)`
      invocando executeProcedure('dbo.FactCatalogoServiciosXidTipoFinanciamiento').
    * Mantiene compatibilidad total con la respuesta del frontend:
      { id, codigo, nombre, precioUnitario, activo, idPuntoCarga, seUsaSinPrecio }.

- backend/src/modules/catalogos/index.js:
    * Se exportó la nueva función `obtenerServicioPorFinanciamiento`.

4. VALIDACIÓN:

- Compatibilidad del frontend verificada sin necesidad de alterar componentes Vue.

6. INTEGRACIÓN DEL PROCEDIMIENTO RetornaFechaServidorSQL:
--------------------------------------------------------------------------------
- Procedimiento utilizado: dbo.RetornaFechaServidorSQL
- Propósito: Obtener la fecha y hora oficial del servidor de base de datos SQL Server
  para evitar desfases por relojes locales descalibrados de los clientes.
- Archivos integrados:
    * backend/src/core/utils/date.js: Función `obtenerFechaServidorSQL()` con fallback
      seguro a Date local en caso de desconexión.
    * backend/src/modules/catalogos/routes.js: Endpoint `GET /api/fecha-servidor`.
    * frontend/src/services/api.ts: Método `catalogosService.getFechaServidor()`.
================================================================================

7. INTEGRACIÓN DEL PROCEDIMIENTO FactOrdenServicioAgregar1:
--------------------------------------------------------------------------------
- Procedimientos utilizados:
    * dbo.FactOrdenServicioAgregar1
    * Inserción en dbo.FacturacionServicioDespacho
- Propósito: Cuando la enfermera planifica un servicio en la nota, se genera
  automáticamente la orden oficial de servicio de GalenHos vinculada a la cuenta
  de atención (@IdCuentaAtencion, @IdPaciente, @IdPuntoCarga=716, etc.) y se registra
  el CPT con su precio de financiamiento en FacturacionServicioDespacho.
- Archivo modificado:
    * backend/src/modules/notas/repositories/notasRepository.js (insertarServicioPlanificado).
- Resultado: Si el sistema web falla o se consulta en el GalenHos de escritorio,
  la orden y el procedimiento CPT aparecen registrados en la atención del paciente.
================================================================================

8. INTEGRACIÓN DEL PROCEDIMIENTO AuditoriaAgregarV:
--------------------------------------------------------------------------------
- Procedimiento utilizado: dbo.AuditoriaAgregarV
- Propósito: Registrar en la tabla oficial de Auditoria de SIGH/GalenHos la creación
  de cada orden de servicio (@Tabla='FactOrdenServicio', @Accion='A', @idListItem=103),
  guardando el ID del empleado, fecha/hora y nombre de máquina.
- Archivos integrados:
    * backend/src/core/utils/auditoria.js: Función `registrarAuditoria()`.
    * backend/src/modules/notas/repositories/notasRepository.js: Invocación en `insertarServicioPlanificado`.
================================================================================
