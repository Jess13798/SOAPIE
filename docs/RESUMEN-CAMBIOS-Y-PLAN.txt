Objetivo: una sola forma de conectarse y una sola configuracion.

Que se hizo:

PASO 2 - PROTEGER LA API                               [ HECHO ]
--------------------------------------------------------------------
Objetivo: que nadie consuma los datos sin estar autenticado.

Que se hizo:
  - NUEVO backend/auth.js: firma y verifica tokens con HMAC-SHA256 usando el
    modulo crypto de Node (SIN dependencias nuevas). Vigencia: 8 horas.
    Exporta firmarToken(), verificarToken() y el middleware requiereAuth().
  - POST /api/login ahora devuelve un "token" cuando las credenciales son validas.
  - Todas las rutas /api/* EXCEPTO /api/login exigen token valido
    (middleware app.use('/api', requiereAuth)).
  - CORS restringido: solo se permiten los origenes definidos en CORS_ORIGIN.
    Un origen desconocido recibe HTTP 403.
  - Frontend: la capa de servicios (api.ts) adjunta el header
    "Authorization: Bearer <token>" en cada peticion; ante un 401 limpia la
    sesion y regresa al login.
  - Login guarda el token; logout lo borra; el router (guard) exige token
    (antes bastaba un sessionStorage falsificable).

Variables nuevas en backend/.env:
  - AUTH_SECRET   = secreto aleatorio para firmar los tokens (mantener privado)
  - CORS_ORIGIN   = origenes permitidos, separados por coma

Archivos:
  - backend/auth.js (NUEVO), backend/index.js, backend/.env
  - frontend/src/services/api.ts
  - frontend/src/views/Login.vue
  - frontend/src/components/AppSidebar.vue
  - frontend/src/router/index.js

Pruebas realizadas (servidor real + peticiones):
  - Sin token ................... 401
  - Token falso ................. 401
  - Token valido ................ 200 (datos reales)
  - Origen permitido ............ 200 + cabecera CORS
  - Origen desconocido .......... 403 (bloqueado)
  - Login invalido .............. 401 (ruta sigue publica)
  - npm run build (frontend) .... compila sin errores

(002-...sql, 003-...sql). Nunca editar uno ya aplicado.

PASO 3 - ROUTERS POR MODULO                            [ HECHO ]
--------------------------------------------------------------------
Objetivo: que backend/index.js deje de crecer con cada modulo clinico.

Que se hizo:
  - Cada dominio tiene su archivo de rutas en:
      backend/src/modules/<modulo>/routes.js
  - Se montan en index.js con:  app.use('/api', <modulo>Routes)
  - backend/index.js quedo como solo "cableado" (middlewares + montaje de
    routers), SIN logica de negocio. Ahora tiene ~55 lineas.

Routers creados:
  - modules/auth/routes.js               -> POST /api/login  (PUBLICO)
  - modules/pacientes/routes.js          -> GET /api/pacientes, GET /api/servicios
  - modules/notas/routes.js              -> GET/POST /api/notas,
                                            DELETE /api/notas/:id,
                                            GET /api/notas/:id/vitals
  - modules/pacientes-sin-cama/routes.js -> GET /api/pacientes-sin-cama,
                                            POST /api/asignar-cama,
                                            POST /api/mover-cama,
                                            POST /api/transferencia-estancia
  - modules/diagnosticos/routes.js       -> GET /api/diagnosticos
  - modules/medicos/routes.js            -> GET /api/medicos

Orden en index.js: authRoutes (publico) -> requiereAuth('/api') -> routers
protegidos. LAS URLs NO CAMBIAN -> el frontend no se ve afectado.

Validado (servidor real + peticiones):
  - /api/servicios .......... 401 sin token / 200 con token
  - /api/pacientes .......... 200
  - /api/pacientes-sin-cama . 200
  - /api/diagnosticos ....... 400 sin parametro / 200 con parametro
  - /api/medicos ............ 400 sin parametro
  - /api/notas .............. 500 (tabla pendiente) igual que antes
  - /api/asignar-cama { } ... 400 (validacion)
  - /api/login .............. 401 (sigue publico)
Los 7 archivos (index + 6 routers) pasan node --check.

Beneficio: cada modulo clinico nuevo (SOAPIE, Kardex, balance hidrico...)
se agrega como un router propio sin tocar un archivo gigante.

PASO 4 - TESTS MINIMOS                                 [ HECHO ]
--------------------------------------------------------------------
Objetivo: detectar si un cambio rompe una funcion clinica sin que nadie lo note.

Que se hizo:
  - Pruebas con el runner nativo node:test (incluido en Node; NO se instala nada).
  - Doble de prueba (mock) de los repositorios -> los tests NO tocan la BD.
  - Se ejecutan con:  npm test

Archivos nuevos (backend/tests/):
  - auth.test.js                    -> firma/verificacion de token, manipulacion,
                                        expiracion y middleware requiereAuth.
  - login.test.js                   -> credenciales validas/incorrectas, usuario
                                        inexistente y error de consulta (bcrypt real).
  - notasService.test.js            -> mapeo de filas, alta, edicion, firma,
                                        borrado e historial de vitales.
  - pacientesSinCamaService.test.js -> asignar/mover cama y transferencia.
  - rutas.test.js                   -> cada modulo exporta un router valido.

Configuracion: en package.json el script "test" pasa de error a:
  node --test "backend/tests/*.test.js"

Resultado: 30 tests, 30 pasan, 0 fallan (~0.75 s), sin tocar la base de datos.

Beneficio: un cambio que rompa una funcion clinica (notas, camas, login,
tokens) falla en `npm test` antes de llegar al hospital.
